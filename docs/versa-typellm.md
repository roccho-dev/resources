# Versa own TypeLLM launcher

`own-typellm-versa` provides the existing `ops-typellm` command with a compile-time fixed
`versapro-own-oci` cipher and the existing target-owned age identity. Its closed CLI accepts
`--envs-sha <40-hex> --ops-sha <40-hex> [--response-metadata]`; it cannot select a target,
key, cipher, package or arbitrary command at runtime. The default dev target is retained.

`own-profile-versa-typellm` composes only this launcher through `mkOwn.extra`. Its Base,
Core and existing default own profile remain the original compositions. The static Versa
profile retains the existing target-bound own Pi and its bounded age initializer; adding the
launcher never runs that initializer or replaces a key. It adds no Jev entry or raw crypto.
The TypeLLM key reaches
only the fixed child environment after current-cipher/recipient and program-build checks.

The envs producer must author the separate `typellm-api.versapro-own-oci` binding using
the existing own public recipient. A dev cipher, OpenCode cipher, or visible key file alone
does not establish this target binding or successful provider use. No plaintext key is a
build input or deployment argument.

Before selecting a Tool generation, compare the current generation source, extra tools
and Pi binding. The static profile is not permission to replace an unknown custom profile.
Use the existing root-owned generation and inactive-client acceptance rules in
[own completion](own-completion.md); retain the previous generation and native rollback.
Do not recreate the age identity, change SSH trust, restart clients, or switch Base/Core.

`oci/dev/proof.sh` exercises the shared launcher with distinct synthetic target keys,
cross-target recipient refusal, missing own cipher, closed argv and exact LF metadata.
`typellm-own-target` checks the composed entry, unchanged Base/Core and the retained own
Pi/initializer derivations. The selected runtime component set must also be compared before
selection; matching a component name is insufficient.
These are source and fixture evidence; deployed source, real TypeLLM use, G1/G2 and return
to the exact original P session require their own runtime evidence.
